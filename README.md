# AI Resume Screening Agent

**Rooman AI Challenge — Junior AI Research Associate**

A runnable NLP-based agent that parses multiple resumes, compares them against a Job Description (JD), ranks candidates, and produces CSV/JSON output with transparent scoring reasons.

## One-line definition

> My agent takes a Job Description and a folder of resumes and produces a scored, ordered shortlist with reasons.

## Why this agent?

I selected the Resume Screening Agent because it demonstrates document parsing, NLP similarity, structured feature extraction, ranking, explainability, batch processing, and reproducible output in one compact project.

## Features

- Reads **PDF, DOCX, and TXT** resumes.
- Extracts candidate name, skills, education signals, and experience signals.
- Processes **10+ resumes in one run**.
- Computes semantic relevance using **TF-IDF + cosine similarity**.
- Computes explicit **skill coverage**, **experience match**, and **education match**.
- Combines the signals into a transparent **0–100 score**.
- Produces an ordered shortlist in **CSV and JSON**.
- Gives concise reasoning plus matched/missing skills.
- Runs locally with **no paid API key** and no network dependency.

## Architecture

```text
Job Description -----------------------+
                                      |
Resume folder -> Parser -> Features --+--> Scoring Engine --> Ranking
                                      |                       |
                                      +--> TF-IDF similarity  +--> CSV
                                                              +--> JSON
                                                              +--> Console
```

## Scoring method

The final score is:

```text
50% TF-IDF cosine similarity
35% explicit JD skill coverage
10% experience match
 5% education match
```

### 1. TF-IDF cosine similarity — 50%

The JD and all resumes are transformed into TF-IDF vectors using unigrams and bigrams. Cosine similarity measures how closely the resume's language aligns with the JD.

Why TF-IDF?
- Fast and deterministic.
- Easy to explain and reproduce.
- Works well for a 10–100 resume challenge-sized dataset.
- Does not require a paid model/API.

### 2. Skill coverage — 35%

The parser detects a curated set of technical skills. Skill score is:

```text
number of JD skills found in resume / number of skills detected in JD
```

This prevents a resume with generic wording from ranking highly only because it shares broad vocabulary.

### 3. Experience match — 10%

If the JD explicitly requires years of experience, the detected candidate experience is compared against it. If the JD has no strict experience requirement, this component does not penalize freshers.

### 4. Education match — 5%

Checks for overlap between education terms in the JD and resume.

## Setup

### Requirements

- Python 3.10+
- pip

### 1. Clone the repository

```bash
git clone <YOUR_PUBLIC_GITHUB_URL>
cd rooman-resume-screening-agent
```

### 2. Create a virtual environment

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

## Run the agent

```bash
python app.py --jd job_description.txt --resumes sample_resumes --out outputs
```

The terminal prints the ranking and creates:

```text
outputs/ranked_candidates.csv
outputs/ranked_candidates.json
```

## Run tests

```bash
pytest -q
```

## Use your own data

1. Replace `job_description.txt` with your JD.
2. Put PDF, DOCX, or TXT resumes into a folder.
3. Run:

```bash
python app.py --jd path/to/jd.txt --resumes path/to/resumes --out outputs
```

## Design decisions

### Why not use an LLM for the score?

For ranking, I wanted the core score to be deterministic, auditable, inexpensive, and reproducible. LLM-only ranking can change between runs and can produce unsupported reasoning. TF-IDF plus explicit features makes every score explainable.

### Why combine semantic similarity and explicit skills?

Pure keyword matching misses context. Pure semantic similarity can reward generic wording. Combining both gives a more balanced result.

### Why a CLI instead of a UI?

The challenge prioritizes a working end-to-end agent over polish. A CLI minimizes setup risk and makes reviewer reproduction straightforward.

## Tradeoffs and limitations

1. **Skill dictionary is curated.** New technologies not in the dictionary may be missed.
2. **Experience extraction is heuristic.** Complex employment timelines are not fully calculated.
3. **PDF parsing depends on embedded text.** Scanned/image-only PDFs need OCR, which is outside this 24-hour scope.
4. **TF-IDF does not deeply understand synonyms.** A sentence-transformer embedding model could improve semantic matching.
5. **Education matching is intentionally lightweight.**
6. **No fairness model is claimed.** The agent should support human screening, not make autonomous hiring decisions.

## What I would improve with more time

- Add sentence-transformer embeddings and compare them with TF-IDF.
- Add section-aware parsing for Skills, Experience, Projects, and Education.
- Add OCR for scanned resumes.
- Add a Streamlit interface with file upload and ranking charts.
- Add configurable scoring weights.
- Add stronger PII minimization and bias checks.
- Add evaluation metrics using a human-labelled benchmark.

## Responsible-use note

This project is a screening-assistance prototype. Hiring decisions should remain with qualified humans. Sensitive or protected attributes should not be used in scoring.
